# 検査記録アプリ (kensa-app) 設計書

作成日: 2026-08-11

## 目的

健康診断・血液検査の結果を記録し、基準値との照合判定と経時推移グラフで
健康状態の変化を追跡する個人用PWA。Google AI Studioで作成した
「検査記録アプリ - 健康診断・検査結果推移トラッカー」を参考に、
既存アプリ群(血圧手帳・運動管理・時間管理)と同じ構成で作り直す。

## 方針(確定事項)

- **技術構成**: ビルド不要の静的PWA(vanilla JS + 自前SVGグラフ)。bp-app方式を踏襲
- **保存・同期**: localStorage + [app-sync共通基盤](https://github.com/taka070600538-tech/app-sync)で
  1日1回 `app-data/kensa-app/backup.json` へ自動バックアップ。
  PC側は既存タスクスケジューラ `AppDataGitPull` がそのまま働く(追加設定不要)
- **公開**: GitHubリポジトリ `kensa-app`(taka070600538-tech)、GitHub Pagesで配信
- **対象ユーザー**: 自分一人分のみ(家族メンバー管理はしない)
- **検査項目**: 参考アプリと同じ15項目

## 画面構成(5タブ)

### 1. ダッシュボード

- 最新検査レコードの15項目を基準値と照合し、「基準内 / 境界値 / 要注意」を
  色分けバッジで一覧表示(カテゴリ別: 糖代謝・脂質代謝・肝機能・腎機能・尿酸)
- 判定結果から自動コメントを生成して表示(下記「自動コメント」参照)
- 検査日・検査施設・満年齢・食後時間、治療内容・備考も表示
- レコードが0件のときは入力を促す案内を表示

### 2. 履歴

- 検査日降順の一覧テーブル(15項目は横スクロール、基準外の値は色付け)
- 行タップで詳細表示(全項目+判定+治療内容・備考)
- 詳細から編集(追加タブのフォームを再利用)・削除(確認ダイアログつき)
- 検索ボックス: 日付・検査施設・治療内容・備考の部分一致で絞り込み

### 3. 追加(編集兼用)

- 基本情報: 検査日(date input)、検査施設(テキスト)、食後時間(数値、空腹時は空欄)
- 満年齢を検査日と生年月日(設定タブ)から自動計算して表示
- 検査15項目の入力:
  - 数値13項目: 空腹時血糖、HbA1c、HDL、LDL、総コレ、non-HDL、中性脂肪、
    AST、ALT、γ-GTP、クレアチニン、eGFR、尿酸(半角数値、未入力可)
  - 定性2項目: 尿糖、尿蛋白(選択式: 未入力 / 陰性(-) / 擬陽性(±) / 陽性(+) / 強陽性(++))
  - **non-HDL**: 総コレとHDLが入力されていれば「総コレ − HDL」を自動計算
    (手動上書きも可能)
  - **eGFR**: 未入力時、クレアチニンと満年齢から日本腎臓学会式(男性)で自動計算
    `eGFR = 194 × Cre^(-1.094) × 年齢^(-0.287)`(小数1桁)。手動入力が優先
- テキスト3欄: 現在の治療・処方内容 / 変更後治療・指示 / 備考・メモ
- バリデーション: 検査日必須。数値項目は数値のみ。すべての検査値が未入力なら保存不可

### 4. グラフ

- 検査項目を1つ選択し、折れ線グラフ(自前SVG)で推移を表示
- 基準値の境界線(正常上限・境界上限など)を水平線で重ねる
- 定性2項目(尿糖・尿蛋白)は 0=陰性 / 1=± / 2=+ / 3=++ の段階値で表示
- データ点タップ(またはホバー)で日付と値を表示
- 選択項目のデータが無い場合は案内を表示

### 5. 設定

- **基準値カスタマイズ**: 項目ごとに正常下限・正常上限・境界上限を編集可能。
  「初期値に戻す」ボタンつき。localStorageに保存
- **生年月日**: 満年齢自動計算用(初期値 1976-09-29)
- **バックアップ**: app-syncの `renderSyncSettings()` をそのまま利用
  (トークン設定・手動保存・復元)
- **JSON書き出し/読み込み**: 全レコードをJSONファイルでエクスポート/インポート
  (インポートは配列形式を検証し、既存データと置き換えるか確認してから反映)

## データモデル

localStorageキー: `kensa-app:records`(レコード配列)、`kensa-app:settings`(基準値・生年月日)

```js
// 1検査 = 1レコード(同日複数可、idはcrypto.randomUUID())
{
  id: "uuid",
  date: "2026-06-20",        // 必須
  facility: "丸の内健診センター", // 任意
  postMealHours: 2.5,          // 任意(空腹時はnull)
  // 数値13項目(未入力はnull)
  fbs: 96, hba1c: 5.4, hdl: 45, ldl: 114, tc: 198, nonHdl: 153,
  tg: 98, ast: 22, alt: 21, ggt: 32, cre: 0.89, egfr: 71.5, ua: 6.1,
  // 定性2項目("-" | "+-" | "+" | "++" | null)
  urineGlucose: "-", urineProtein: "-",
  // テキスト3欄
  currentTreatment: "", newTreatment: "", memo: ""
}
```

## 基準値(デフォルト・男性基準)

設定タブで編集可能。判定は「基準内 / 境界値 / 要注意」の3段階。

| 項目 | 単位 | 正常範囲 | 境界域 | 要注意 |
|---|---|---|---|---|
| 空腹時血糖 (fbs) | mg/dL | 70–99 | 100–125 | ≥126 (または <70) |
| HbA1c (hba1c) | % | 4.6–5.5 | 5.6–6.4 | ≥6.5 |
| HDLコレステロール (hdl) | mg/dL | ≥40 | 35–39 | <35 |
| LDLコレステロール (ldl) | mg/dL | 60–119 | 120–139 | ≥140 |
| 総コレステロール (tc) | mg/dL | 140–199 | 200–219 | ≥220 |
| non-HDL (nonHdl) | mg/dL | 90–149 | 150–169 | ≥170 |
| 中性脂肪 (tg) | mg/dL | 30–149 | 150–299 | ≥300 |
| AST (ast) | U/L | ≤30 | 31–35 | ≥36 |
| ALT (alt) | U/L | ≤30 | 31–40 | ≥41 |
| γ-GTP (ggt) | U/L | ≤50 | 51–100 | ≥101 |
| クレアチニン (cre) | mg/dL | 0.65–1.00 | 1.01–1.29 | ≥1.30 |
| eGFR (egfr) | mL/分/1.73m² | ≥60 | 45–59 | <45 |
| 尿酸 (ua) | mg/dL | 2.1–7.0 | 7.1–8.9 | ≥9.0 |
| 尿糖 / 尿蛋白 | — | 陰性(-) | 擬陽性(±) | 陽性(+)以上 |

- HDL・eGFRは「下限型」(低いほど悪い)、他の数値項目は「上限型」
  (空腹時血糖・クレアチニン・尿酸は下限も持つが、判定コメントは上限側を主とする)
- 正常範囲を外れ境界域内 → 境界値、境界域も外れる → 要注意

## 自動コメント(ダッシュボード)

最新レコードの判定結果から、該当するものを箇条書きで表示:

- 糖代謝: fbs≥126 または hba1c≥6.5 →「糖尿病域の数値です」/
  境界域 →「境界型(糖尿病予備軍)」
- 脂質代謝: ldl 要注意 →「高LDLコレステロール血症」、境界 →「軽度高コレステロール」/
  tg 要注意 →「高トリグリセリド血症」、境界 →「中性脂肪軽度高値(境界域)」
- 肝機能: alt 要注意 →「ALT上昇」、境界 →「ALT軽度高値」
- 腎機能: egfr <60 →「eGFRの低下」
- 尿酸: ua >7.0 →「高尿酸血症」
- すべて基準内 →「すべての主要項目が良好です!」

## エラー処理

- localStorage読み込み失敗(壊れたJSON)→ 空配列で起動し、コンソールに警告
- app-sync読み込み失敗(オフライン)→ 無視してアプリ本体は動作
- インポートファイル不正 → alert表示、既存データは変更しない
- 数値入力の全角・非数値 → バリデーションエラー表示、保存させない

## テスト(node:test、依存なし)

- `reference.js`: 各項目の3段階判定(境界値ちょうどのケースを含む)、カスタム基準値の反映
- `calc.js`: non-HDL計算、eGFR推算式、満年齢計算(誕生日前後)
- `comments.js`: 判定結果からのコメント生成(良好時・複数該当時)
- `records.js`: CRUD・検索・ソート
- `backup.js`: payload構築・復元検証・不正データ拒否
- `chart.js`: SVG生成(データ点・基準線の座標)
- PWA資産の存在チェック(bp-appのpwaAssets.test.js相当)

## 実装手順(概要)

1. リポジトリ初期化・純ロジック(items/reference/calc/comments/records/backup/chart)をTDDで実装
2. UI(5タブ)+PWA資産
3. app-sync組み込み・GitHubリポジトリ作成・Pages公開
4. 本体(Fable 5)がテスト・実機動作確認
